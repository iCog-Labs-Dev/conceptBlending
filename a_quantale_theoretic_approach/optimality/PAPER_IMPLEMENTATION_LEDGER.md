# Paper-to-code implementation ledger

Authoritative source: `a_quantale_theoretic_approach/quantale_blending_paper (2).pdf`.
Equation and definition numbers below refer to that paper.

This ledger distinguishes three states:

- **Implemented:** executable PeTTa semantics and contract tests exist.
- **Partial:** supporting primitives exist, but the paper-level condition is not wired.
- **Missing:** the normative PeTTa implementation still needs to be written.

Python optimality code is treated as an earlier executable approximation. PeTTa is the
normative implementation target for the integrated pipeline.

## Deliberate quantale correction

Paper Equations (11) and (13) describe the truth-value alternative operation as bounded
addition. Bounded addition is not idempotent and therefore is not the lattice join for the
usual order on `[0,1]`. The implementation deliberately uses `max`, as agreed for this
project:

| Product component | Tensor | Join | Unit | Bottom | Order |
| --- | --- | --- | --- | --- | --- | --- |
| possible worlds | intersection | union | all worlds | empty set | subset |
| truth value | multiplication | maximum | `1` | `0` | numeric `<=` |

This correction is implemented in `core_representation/quantale_types.metta` and covered
by the quantale-law tests.

## Optimality constraints

The paper defines six scalar factors. “Topology (Web)” is one factor in Table 1. The PeTTa
evaluator emits separate Topology and Web diagnostics, as required by the pipeline, but
combines them by lattice meet into one vital-relation-coherence factor before Equation (36),
so they are not multiplied twice.

| Constraint | Paper condition | Current PeTTa status | Required correction |
| --- | --- | --- | --- |
| Integration | actual V-colimit, Equations (29)-(31) | **Implemented for finite supplied comparison scope** | `q-vcolimit-integration-op` validates a `VColimit` certificate; the legacy property-only path reports `Pending` |
| Topology | vital-relation coherence, Equations (26)-(28) | **Implemented** | `q-topology-op` meets double-coend preservation scores for both source relation families |
| Web | cross-space relation correspondences | **Implemented independently** | `q-web-op` checks explicitly supplied `VitalRelationCorrespondence` evidence through both source-to-blend maps |
| Unpacking | V-split cocone maps, Equations (32)-(33) | **Implemented** | `q-unpacking-op` consumes explicit blend-to-source reconstruction morphisms and no longer aliases Good Reason |
| Good Reason | blend generated by joined input contributions, Table 1 | **Implemented with evidence** | Every candidate property requires a valid `PropertyEvidence` value and non-empty provenance; missing evidence yields bottom or `Blocked` |
| Metonymic Tightening | relation strengthening through `G`, Equations (34)-(35) | **Implemented** | `q-metonymic-tightening-op` evaluates generic-mediated relation paths by residuation |
| Relevance | weighted/filtered colimit, Table 1 | **Implemented with evidence** | `q-relevance-evidence-op` weights genuine quantale evidence; absence or malformed evidence is `Blocked` |

The paper's unified score is Equation (36):

```text
Opt(C) = Integration
         tensor VitalRelationCoherence
         tensor Unpacking
         tensor GoodReason
         tensor MetonymicTightening
         tensor Relevance
```

Until Hom extraction and relation evidence are available, a missing constraint must be
reported as `Pending` or `Blocked`. It must not contribute a fabricated unit value.

This is now enforced by `VConstraintResult`. The legacy five-argument evaluator reports
its unavailable enriched constraints as `Pending`/`Blocked` and gives the aggregate `Opt`
bottom. The full `q-enriched-optimality-evaluator` returns `Evaluated` only when every
constraint has the required evidence.

## V-colimit certificate contract

```metta
(VColimit Name Cocone
   (MediatingWitnesses
      ((MediatingWitness ComparisonCocone Mediator) ...))
   (ComparisonScope (ComparisonCocones ...) Exhaustive))
```

Validation checks:

1. all categories through the V-category checks required by every morphism;
2. every span and cocone morphism;
3. candidate and comparison cocone commutativity;
4. mediator source and target endpoints;
5. both mediator triangles;
6. enriched-Hom preservation through `ve-vmorphism-valid`;
7. exactly one valid mediator for every comparison cocone;
8. no witness outside the comparison scope and no duplicate comparison cocones.

The certificate is a relative finite universal-property check: `Exhaustive` is an explicit
contract asserted by the component that enumerates the supplied comparison cocones. The
checker does not claim to enumerate every small V-category internally.

## Enriched optimality context

The legacy spelling remains accepted:

```metta
(VOptimalityContext
   Candidate VColimit
   SourceRelationsA SourceRelationsB BlendRelations
   CrossSpaceCorrespondences
   GenericToA GenericToB AToBlend BToBlend
   BlendToA BlendToB
   PropertyEvidence RelevanceEvidence)
```

It is normalized into `VOptimalityInputs`, validated once, and materialized as:

```metta
(VSharedOptimalityContext
   Perspective Universe Candidate VColimit
   SourceRelationsA SourceRelationsB BlendRelations
   TransportedRelationsA TransportedRelationsB
   CrossSpaceCorrespondences
   GenericToA GenericToB AToBlend BToBlend
   BlendToA BlendToB
   PropertyEvidence RelevanceEvidence)
```

`q-build-optimality-context` checks candidate/family perspective agreement,
candidate/quantale universe agreement, all required V-morphisms, and every
generic/source/blend category endpoint. It computes each source relation family's
companion/conjoint double-coend transport exactly once. Topology and Web consume
these cached families, so both constraints inspect the same mathematical transport.

It returns `VOptimalityResult Evaluated` and the tensor product only when all seven
implemented checks are evaluated. Any absent Hom map, relation family, reconstruction,
provenance, relevance evidence, or colimit certificate makes the aggregate `Blocked` with
quantale bottom.

## Staged pipeline integration

`optimality/optimality-integration.metta` consumes the existing producer records:

```metta
(structural-blend-preparation ...)
(QuantaleVPredicateColimitResult ... (Blend Candidate) ...)
(OptimalityEnrichmentArtifacts
   VColimit SourceRelationsA SourceRelationsB BlendRelations
   CrossSpaceCorrespondences
   GenericToA GenericToB AToBlend BToBlend
   BlendToA BlendToB PropertyEvidence RelevanceEvidence)
```

The adapter checks that the structural generic concept and perspective equal the
colimit candidate's name and perspective, constructs the shared context, and invokes
the completed evaluator. Missing enrichment artifacts, mismatched producer records,
or invalid category endpoints return `OptimalityIntegrationResult Blocked` with
quantale bottom and a specific reason.

When explicit `PropertyEvidence` is absent, the adapter derives Good Reason evidence
from the colimit result's `PropertyContributionMap`. Explicit property evidence remains
available for provenance contributed by the generic-space or another producer.

This is intentionally a staged data boundary. It does not import and rerun the
V-predicate extraction, generalization, or colimit engines in the same PeTTa session.
Their results can be cached and passed as inert records without duplicate transitive
imports. The future Hom extraction/building pipeline owns construction of
`OptimalityEnrichmentArtifacts`; until it supplies them, integration correctly blocks.

For executable whole-pipeline validation, `integration/complete-blend-pipeline.metta`
does run the cached Cartesian generalizer, the world-aware quantale colimit, and
the enriched optimality evaluator in one PeTTa call. Its contract consumes the
compact V-predicate extractor output plus the later GNN scalar assignment. The
runtime fixture verifies that absent scalars are `Pending`, absent enriched-Hom
artifacts are `Blocked`, and complete evidence is `Evaluated`.

## Runtime data contracts

### Vital relation

```metta
(VitalRelation
   RelationName
   Perspective
   (VProfunctor RelationName Category Category Values)
   Provenance)
```

`Values` is a finite matrix of:

```metta
(SourceObject TargetObject (Q Worlds Degree))
```

The validator requires:

1. a non-empty perspective;
2. a valid V-profunctor;
3. identical source and target categories, making it an endo-profunctor;
4. quantale values in the category's shared world universe.

### Vital-relation family

```metta
(VitalRelationFamily Perspective Category Relations)
```

All relations must be valid, share the family's perspective and category, and have unique
names. This is the input contract for the later Topology/Web implementation.

### Public coend

```metta
(ve-coend SourceObject TargetObject FirstProfunctor AfterProfunctor)
```

The operation validates both profunctors, their common middle category, and both endpoints.
Malformed input returns a specific `VError`; valid input returns one `Q` value. Full matrix
composition remains available through `ve-vprofunctor-compose`.

## External evidence still required at runtime

Vital-relation preservation and the Hom-based constraints must consume, rather than invent:

- V-categories built from source, generic, and blend algebraic specifications;
- enriched Hom values from the planned Hom extraction/building pipeline;
- source-to-blend and generic-to-source V-morphisms/profunctors from the colimit pipeline;
- source and blend vital-relation families, scoped by perspective;
- contribution provenance from V-predicate extraction and colimit construction.

The optimality module validates and aggregates these inputs, but does not silently
replace absent Homs or relations with semantic-name similarity. The staged adapter now
enforces that contract; Hom/relation generation itself remains a separate planned
component.
